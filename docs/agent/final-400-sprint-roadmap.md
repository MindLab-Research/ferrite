## 0. 判决（先读这九条）

**A. 400 不是「一个数字」，是「任务口径 × 步时」的乘积约束。** 三条独立方程（§2.3）：

| 任务口径 | mean_k | tok/step | 400 需要的步时 | 可达性（今天架构 + 已规划优化） |
|---|---:|---:|---:|---|
| **计数/模板**（数字 1-200） | **5.0 ✅实测** | 6 | **≤ 15ms** | **✅ 可达**（`B4→B7` 之间） |
| **一般散文/对话**（用户要的 2-3） | 2-3 | 3-4 | **≤ 10ms**（或 7.5ms @ accept 2） | **⚠️ 需 L4/L5 + accept 修复双到位** |
| **出师表**（文言+罕见字） | 1.2 ✅实测 | 2.2 | **≤ 5.5ms** | **❌ 物理不可达**（低于 L5 地板 8~9ms） |

**B. 今天最重要的一条架构判决反转了主攻方向：`LAZY_VERIFY` 是生产臂，不是 `SWALLOW_STEP`（batched）。**
`lazy` 蕴含 swallow（row 0 = 被吞的主链步 ⇒ 白拿 −4.55ms），且在 tiny-SIMT 架构下
**batched 恒 6 行、lazy 只跑 k_emit≈2.2 行** ⇒ 低 accept 下 lazy 结构获胜（22.5 vs 39ms，差 16.4ms）。
**batched（SWALLOW）只在 `mean_k ≥ 3.55` 时才该投入**。→ 生产形态 = 「SWALLOW 常开 + lazy⇄batched 走路由」。

**C. 性能大头是共享专家 + routed experts ≈ 19ms，Wave 1 一个都没碰。**
`shered 10.4 + routed 8.3 = 18.7ms = 50.1%`（m=5 口径）。这就是为什么「图化/launch」全是小钱：
**约束是「tiny kernel 的 μop 数 + 3~4 warps/SM 的延迟暴露」，不是字节（1.84ms=5%）也不是 submit（图=−1.5ms）。**

**D. accept 的天花板是 5，不是 1.214。** `DSPARK_DRAFTS=5`；计数任务**实测 k_acc=5 5 5…5**。
1.214 是**出师表这个任务**的数，不是引擎的数。用户的「2-3」是**一般散文**口径，
与 sglang `arena-hard mean-k 2.78` 完全吻合；到 2-3 需 `p: 0.563 → 0.71~0.83`（+0.15~0.27 绝对）。

**E. 质量退化（77% 重复率）= 模型行为，不是 spec-decode。** EAGER 对照同样退化（甚至更重）。
⇒ **不是工程 bug，不列入 400 冲刺的修复项**（但它限制了对话任务的可达性）。

**F. 今天是「三条阻塞全部解开的临界点」**：SH_PAIR parity 修复已提交（幻影行 + 测试 bug）、
tcgen05 对齐守卫已入（待重测）、SWALLOW 的 ar5-hang 由 Plan B（unanimity-or-direct）定案。
**⇒ 明天起可以从「排障」切换到「兑现」。**

**G. 唯一能到 400 的步时通道是 L4（占用/MLP）**：`−5~8ms / 16~21 人日 / 仓内零实测背书`
（v17→v21 四变体全中性）。**其余所有项（B1~B6）加起来落在 ~17~30ms ⇒ 200~350 tok/s，不是 400。**

**H. 关键路径 = `M1 口径 → M2 零成本 → M3 SH_PAIR → M4 tcgen05 → M5 B 类 → M6 L4`。**
accept 支线（oracle / SEED_ALIGN / draft e4m3 / top-k）**并行**，不占关键路径的 GPU 位。

**I. 每条数字都必须按「实测 / 设计 / 理论」三级标注**（§3）。今天的 15 条发现里有
**4 条是实测**（accept 5 / 对话 0.96 / EAGER 77% / mrows −1.21 / 图 −1.5），其余是设计口径——
历史兑现率 **≈60%**（`swallow-unlocked §2`），必须按此折算票面。

### 2.3 到 400 的三条算术（不可混淆）

```
（1）计数口径（accept 5，tok/step 6）：6 × 1000 / 15ms = 400  ⇒ 步时 ≤15ms
（2）用户口径（accept 3，tok/step 4）：4 × 1000 / 10ms = 400  ⇒ 步时 ≤10ms
（3）用户口径（accept 2，tok/step 3）：3 × 1000 / 7.5ms = 400 ⇒ 步时 ≤7.5ms（近 L5 地板）
```

### 2.4 诚实票面（按历史 **60% 兑现率**、且 mrows 按 ≈0 计）

```
39.0 (实测)
 − 1.5  (图)              ✅实测
 − 1.0  (hc, 60%)

 − 1.5  (tcgen05, 60%)
```

**400 必须靠 L4 把 17ms 推到 ~15ms——这是唯一能把票面从 350 抬到 400 的一项。**

## 4. 关键路径（串行主干）与并行支线

```
[串行主干 —— GPU 位唯一，必须按序]
M1 口径/真值(nsys) ─→ M2 零成本(lazy+hc) ─→ M3 SH_PAIR(parity门) ─→ M4 tcgen05(微基准门)
                                                                    │
                                                                    └─→ M6 L4(K-split→down→MLP) ─→ 400

[并行支线 —— 不占主干 GPU 位]
accept 支线：  P3-1 oracle → P3-2 SEED_ALIGN → P3-3 draft e4m3 →（P3-4 top-k，须仲裁）
B 类支线：     P2-3 B6（0.5 人日，可与 M3/M4 并行）
正确的顺序理由：
  1. M2 必须最先（零成本、且 H1/H2 判据决定后续一切）；
  2. SH_PAIR 排在 tcgen05 前（parity 已修 = 低风险先拿；tcgen05 从未上 GPU = 高风险）；
  3. L4 排在 tcgen05 后（L4-3/L4-4 是 tcgen05 的收尾，无 L2/L4-3 则 L4 无靶）；
  4. 「Plan B（图）」不在关键路径（只值 −1.5ms，已实施）——它是**正确性工具**，不是性能项。
```

## 6. 风险缓解（每步失败时的 fallback）

| 风险 | 触发信号 | Fallback |
|---|---|---|
| **SWALLOW 假解锁**（ar5-hang 是竞态，一次 0 不代表修好） | 3 次运行任一 hang / 长跑跨过历史步数后 hang | 回 `SWALLOW_STEP=0`；**lazy 路线不受影响**（m=1 图无 ar5-hang） |
| **Plan B 是 workaround 不是根因** | 换 gate 组合后 hang 新形态复现 | 记录已知缺陷，**保留 SWALLOW 无图作生产形态**（已验证 0 hang）；`VERIFY_HEAD_MROWS` 单独成轮 |
| **mrows 族兑现率 0**（`SH_EXP` 两次零收益先例） | 每个 gate 单独 A/B 后 `verify_ms` 位移 <40% | 停 P1-3，转 P2（ms 账更大）；**不要在同一轮叠 gate 找感觉** |
| **SH_PAIR parity 修不动** | 诊断树走完仍无单一根因 | 冻结 `SH_PAIR_M=0`，−5ms 从阶梯划掉（落点下修一格） |
| **tcgen05 红线**（`tc5::e4x` 从未上 GPU） | 冒烟拉丁 / 非法指令 | 立即关路径，**不投变体矩阵**（勿重演 v17→v21） |
| **e4m3 × tcgen05 互斥**（正确性 vs 性能正面冲突） | tcgen05 需回 e2m1 激活 ⇒ opa 问题复现 | **上报用户拍板**；或先改 kernel 的 `act_e4m3` 分支 |
| **L4 投入陷阱** | `L4-1` 单独 A/B 中性 | 不在 L4 开新变体矩阵，除非 P2-2 已给出 routed 实测新地板 |
| **口径漂移**（三计时器混用） | serve 墙钟 vs 内部计时 vs nsys 不一致 | 一切账按 nsys；阶梯每条标「臂 + m」 |
| **零拉丁回归**（用户硬要求） | 四段文本出现拉丁碎片 | 回退该 commit；单 gate 单 commit + 读回 |
| **5 分钟预算超时**（用户硬要求） | 单次会话 >5 min | 切小测试（`MAXTOK` 限量）；nsys 用 `--capture-range` 或短跑 |

## 8. 一句话交付

> **400 是「任务口径 × 步时」的乘积约束，不是单一数字**：计数口径（accept 5）需步时 ≤15ms，
> 用户口径（accept 2-3）需 ≤10ms，出师表口径需 5.5ms（物理不可达）。
> **今天的三条阻塞（SH_PAIR parity / tcgen05 对齐 / ar5-hang）全部解开**，主攻方向定为
> **lazy 生产臂（蕴含 SWALLOW）+ 融合/换核（SH_PAIR → tcgen05 → B 类）+ L4 占用**。
> **关键路径 = M1 口径 → M2 零成本 → M3 SH_PAIR → M4 tcgen05 → M5 B 类 → M6 L4**；
> **400 的第一个可达点是 M6（L4 落地，25~44 人日）**，且**只对计数口径成立**。
> **诚实票面**：不上 L4，全融合按 60% 兑现 = ~29.5ms ⇒ **203 tok/s**；
> **上 L4 才到 ~11~14ms ⇒ 430~545 tok/s（400 ✓）**。**L4 是唯一一道门，其余都是垫脚石。**
